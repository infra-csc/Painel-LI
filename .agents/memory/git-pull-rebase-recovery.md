---
name: Git pull recovery
description: Recovering Pull operations that leave an apparent rebase, merge, or index lock in the Replit Git UI.
---

When the Git UI reports an unsupported rebase/merge or a locked index, inspect `git status`, `.git/rebase-*`, `.git/MERGE_HEAD`, active Git processes, and `.git/index.lock` before taking action. Resolve staged conflicts and continue the existing operation; remove `index.lock` only when no Git/editor process is active. If a rebase is trying to replay many local commits over a small number of remote commits, prefer aborting that rebase and merging the remote snapshot while preserving both histories.

**Why:** The Git UI can start a Pull/rebase independently of the agent and can remain on a stale editor or lock state after a previous operation, while the workspace itself is still recoverable. Aborting alone may only temporarily clear the error: the UI can immediately issue another `pull --rebase`, even when `pull.rebase` is configured false, because its command explicitly requests a rebase. Integrating the remote commits clears the current divergence, but if another contributor advances the remote while many local commits remain unpublished, the next UI Pull can repeat the same failed rebase. Unsetting upstream prevents this but also removes Pull from the Git pane. In one recovery the upstream reappeared after an abort, and the UI immediately retriggered the rebase; a single clean status check was not enough. During that rebase, checking out the remote tip made a workflow configured only on local main disappear from Replit's workflow list; aborting restored it. Configuring a new workflow may also attach it to the Project run button automatically, so a Git-updating workflow must be separated from normal app startup. A workflow's Git process may lack committer identity even when an interactive shell has one. Reconnecting GitHub under account Git Providers did not supply credentials for this workspace's HTTPS shell push; fetch worked, but even a push dry-run returned "Invalid username or token".

**How to apply:** Never start another Pull over an existing operation. Finish or abort the detected rebase/merge first; if aborting, merge the remote tip when syncing is intended, resolve actual conflicts without discarding local commits, and validate that there are no unmerged files or conflict markers. Restoring the native Git-pane Pull safely requires aligning the remote via push only after the user authorizes updating the shared branch. Without a push, offer a separately runnable, guarded fetch+merge action and protect against UI-initiated rebase using the local guard described below. Removing upstream can hide Pull temporarily, but is not reliable prevention when the UI reattaches it. Inspect the Project run-button tasks to ensure starting the app cannot trigger the Git-updating action. Re-check tracking and rebase state after other operations, and give automated merges a command-scoped agent identity rather than relying on global Git settings. If authorized push is blocked by HTTPS authentication, do not assume a Git Providers reconnect fixed shell credentials: check a dry-run, then request a narrowly scoped token through the secure Secrets flow rather than chat. Do not reset or skip commits to silence the UI.

## Local rebase protection

Protect unpublished main history with a local pre-rebase guard rather than relying only on removing upstream.

**Why:** Repeated UI Pull operations reattached upstream and restarted the same conflicting rebase after every remote update. Removing upstream and aborting were temporary recovery measures, not reliable prevention. A guard can reject the rebase before checkout while still allowing fetch+merge.

**How to apply:** Preserve existing hooks, limit the protection to main with unpublished commits, and verify it against an actual divergent `pull --rebase` in a disposable repository. Hooks belong to the local clone and are not automatically installed in a fork or fresh checkout. Do not bypass the guard unless a deliberate rebase is requested and its history-rewrite consequences are understood.
